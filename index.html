Relationships

Parents and children use the same action table

action X (batch) └─ action_revision X:r1 └─ action_member → child A:r3, child B:r2, child C:r1 approve X:r1 → action_approval └─ action_approval_target → selected A:r3, B:r2 └─ action_attempt → receipt / provider readback child C:r1 stays open. A new child D never joins this approval. action_link records derivation, dependencies and supersession.

Every relationship carries organization scope. Composite foreign keys prevent cross-org links and revisions belonging to the wrong action. Membership and approval targets are immutable.

Ownership & history · every parent and child

A child is a full ticket.

Its own permanent URL, current owner, content revisions, approval, execution attempts and audit trail. Parent membership is a relationship—not a lesser type of record.

Created by

Original human, agent or system principal. Immutable creation event.

Assigned to

Who is responsible now. Reassignment records old owner → new owner, actor, reason and time.

Approved by

Actual authorizing principal, exact revision, selected child revisions, server timestamp and command ID. Never inferred from assignment.

Performed by

Human actor or agent/system identity, execution attempt and initiating user where applicable. Automation names its policy version.

History rules and schema fields

Actor identity: actor_kind (user / agent / system), actor_id, optional initiated_by_user_id, and policy_id + policy_version for automation. Actor identity is required for every accepted mutation.

Audit event: event_id, organization_id, action_id, action_version, command_id, event_type, actor, occurred_at (server time), revision references, before/after references, reason, and evidence links.

Keep the evidence: retain actor attribution when a user leaves. Use an approved retention policy for deleted identities; do not cascade-delete approvals or invent a current name. Never silently rewrite an audit event.

Parent approval: one approval record with immutable selected-child targets. Every child exposes that approval and its approver. A child approved separately has its own approval; the parent shows the mixture honestly.

Parent history: show parent events plus linked child events with their original IDs and timestamps. Do not copy child events into a second contradictory history. Parent progress is derived.

Approval is not assignment: changing the owner does not transfer or invalidate historical attribution. Policy decides future command permissions. Uncertain execution stays visible even if the ticket is reassigned.

Simpler does not mean fewer tables. It means fewer competing truths. These records make facts explicit that are currently hidden in JSON, reused rows, personal overlays and queue memory.

Keep and extend

Domain models & proven guards

agent_request / agent_run remain Agents-owned work intent and execution. Their state becomes linked domain facts, not a competing inbox approval model.

Reviews, experiments, listings, campaigns remain domain-owned. Action revisions freeze what was authorized; they do not replace provider/domain records.

Capability manifest, grants, receipts, readback adapters, BullMQ, RLS remain. Execution evidence gets explicit action/revision/attempt links.

Compatibility only

History is not garbage

Preserve old URLs with action_legacy_alias. Keep raw migration snapshots and existing review rejection / recovery proof records.

Ambiguous reused batch IDs resolve to history, not falsely to the newest batch. Unknown legacy types stay readable and blocked.

Old columns, adapters and overlays are removed only after backfill checks, compatible worker cutover, and the rollback window.

The simplification: one identity format, one revision rule, one organization-shared command path, one recovery protocol, and one inbox query—across localizations, reviews, requests and advisory work.
