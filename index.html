Blocking gaps corrected in the plan

What changed after review

Strict types

No JSON/JSONB, serialized payloads, arbitrary key/value fields, open metadata or catch-all variants. Closed contracts from database to UI.

Resource conflicts

Two tickets targeting the same review or listing also serialize at dispatch. Ticket locks alone are insufficient.

Uncertain writes

Reconcile the earlier write before editing or approving replacement content. Preserve late provider evidence.

Partial approval

One root command plus an approval event for every selected child. All commit together, with exact revision and membership references.

Generation

Generated content needs its own human or explicit policy authorization. Approving generation cannot approve unseen copy.

Migration

Real migration replay, final writer handoff, then removal of old authorities. No indefinite dual model.

Review status: the fourteen-table design is withdrawn. This smaller candidate needs a field-complete schema, migration fixtures and concurrency proofs. Table count alone is not architecture validation.

Ownership & history · every parent and child

A child is a full ticket.

Its own permanent URL, current owner, content revisions, approval, execution attempts and audit trail. Parent membership is an explicit relationship between full tickets.

Created by

Original human, agent or system principal. Immutable creation event.

Assigned to

Who is responsible now. Reassignment records old owner → new owner, actor, reason and time.

Approved by

Actual authorizing principal, exact revision, selected child revisions, server timestamp and command ID. Never inferred from assignment.

Performed by

Human actor or agent/system identity, execution attempt and initiating user where applicable. Automation names its policy version.

History rules and schema fields

Actor identity: actor_kind (user / agent / system), actor_id, optional initiated_by_user_id, and policy_id + policy_version for automation. Actor identity is required for every accepted mutation.

Audit event: event_id, organization_id, action_id, action_version, command_id, event_type, actor, occurred_at (server time), revision references, named variant-specific fields, reason, and evidence links.

Keep the evidence: retain actor attribution when a user leaves. Use an approved retention policy for deleted identities; do not cascade-delete approvals or invent a current name. Never silently rewrite an audit event.

Parent approval: one command event plus a typed approval event for each selected child, committed together. Every child exposes that approval and its approver. A child approved separately has its own approval; the parent shows the mixture honestly.

Parent history: show parent events plus linked child events with their original IDs and timestamps. Do not copy child events into a second contradictory history. Parent progress is derived.

Approval is not assignment: changing the owner does not transfer or invalidate historical attribution. Policy decides future command permissions. Uncertain execution stays visible even if the ticket is reassigned.

Strict at every boundary: closed TypeScript unions, strict wire validation, typed repository ports, database enums/checks/FKs and immutable history. Untrusted input is parsed once; no open payload reaches Core or a worker.

Clean final schema

Preserve facts. Delete old authority.

Import surviving content, actors, receipts and links into typed rows. Index historical source IDs on import events for old URLs; reused batch URLs resolve to history when ambiguous.

Rehearse expand, backfill, writer handoff and contract/drop migrations. Remove old tables/columns, JSONB parameters, source-specific command code and recovery writers from this path.

Raw forensic exports remain migration evidence only. No old payload blob becomes an executable fallback. Missing history is marked honestly.
