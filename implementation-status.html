What happens to a piece of work

  1. 1 · ProposeCreate one ticket and seal the exact content. New copy becomes a new revision.
  2. 2 · ApproveRecord the actor, revision and Undo deadline in one server transaction.
  3. 3 · DeliverPersist the attempt before a provider call. SQL retains work if a worker or queue fails.
  4. 4 · VerifyKeep acknowledgement, published content and an uncertain request distinct.

Shared work, personal reads

Approval, ownership, holds and outcomes belong to the organization. Marking something read changes only that person’s watermark.

A batch is still a ticket

Membership pins permanent child tickets and their revisions. New reviews cannot silently join an approved batch. Progress is derived from its children.

One owner for each fact

Actions owns workflow. Domain schemas own content. Provider schemas own native identities and receipts. Composition selects the immutable contract.

Queues only wake workers

There is no replacement generic jobs table. Execution records represent accepted obligations and attempts; existing queues transport wake-ups.

No work hidden behind a limit

The new read layer pages through root tickets, children, archived work, exact batch membership and history. Page size limits each response, not how much work you can reach.

  1. 1 · ScopeBind the organization and filters. A cursor cannot change that scope.
  2. 2 · SelectUse one database snapshot for the eligible IDs and exact total.
  3. 3 · LoadFetch content only for those IDs. History selects IDs before its wide joins.
  4. 4 · ContinueReturn a precise cursor and next page. Deleted anchors do not break it.

Stable ordering

Microsecond timestamps and a deterministic ID tie-breaker preserve equal-time rows. A changed live batch requires a restart; historical membership stays pinned.

Honest counts

Counts and pages share the same eligibility rules. Parent placement does not expose its children twice. Package totals include all current members, across app filters.

Five decisions asking for you

The cap is per app. It limits new work asking for client attention; it never hides an existing obligation or prevents an outcome from being recorded.

Counts toward five

An open actionable child or leaf ticket counts once. Approved work counts only when its current recovery owner is the client. A package with two required children uses two slots, even when shown as one row.

Uses no slot

Approved work waiting on Apple, another provider or Fload recovery; optional advisories; historical records. An open parent does not count its children twice. Its own operation can separately need client recovery.

Cannot lose a slot in a race

Commands, producers and execution facts serialize through one app admission guard. Every target reserves its contribution before any accepted batch is written. Two requests cannot both take the last slot.

Truth may exceed five

Undo or an existing obligation that starts needing the client can take the total above five. New discretionary work then waits. Read, snooze, schedule and archive do not free a required-decision slot.

Organization-wide work remains visible outside a per-app cap. The inbox total counts visible tickets; this separate admission metric counts independently required decisions. Neither is an approximate page length.

  4. 4 · Tell the truthPublished content can complete an acknowledged write. An uncertain write stays uncertain, even when its content matches.
