Approve now. Keep it visible until it is done.

An approved listing can wait for a release or a chosen month. Its ticket, authorization and history survive the wait.

03 / WHAT GETS SIMPLER

Fewer competing answers.

Normalization is about giving each fact one home. The cleanup removes duplicate authority and temporary identities.

Patterns being replaced
Read, snooze and workflow mixed togetherPersonal activity can overwrite shared work state.
Drafts and batches rebuilt for the inboxIdentity changes when source rows stop being pending.
Browser timers and competing write pathsA screen can appear accepted before delivery is durable.
Separate capped list and count logicWork can disappear from reach or disagree with the badge.
Proposed replacement
One shared lifecycle + personal read stateEach has its own explicit fields and rules.
Permanent tickets + versioned membershipCompletion changes progress, never identity.
One command path + server-owned deliveryAccepted work survives browser and worker failures.
One filter definition + paginationLists and counts describe the same set of work.

Postgres: durable obligation→BullMQ: delivery transport→Worker: attempt + recovery

Use the existing queues. A recovery scan redelivers due database work after a lost enqueue. Queue completion alone never means the provider change is verified. An unknown result stays explicit; retry cannot assume a lost write failed.
