What has actually changed

Published feature head f1db52b43 removes the duplicate listing source and forced Chromium setup, reuses the existing SRP transport, and routes durable review writes through the existing authorization kernel. Speculative account-wide locking and additional browser-execution drafts have been archived and removed.

Existing Apple listing clients now handle scoped API pagination and reject incomplete or contradictory results. The session wrapper preserves both operation and lifetime cancellation. Both former CI failures have regression fixes.

Validation: 1,087 Actions SQL tests across 105 files passed at 9f411aa3f, including fresh and repeated migration replay. The final cleanup head passes API typecheck, MCP build/typecheck and 37 affected SQL tests. The pagination delta passes 528 Apple and 54 API tests plus independent review. Final remote CI is pending.

Not finished: production permissions and entitlement composition, exclusive old-sender handoff, UI/entrypoint journeys, and migration with retirement of the old lifecycle remain required. No production deployment or main merge.

The intended ownership

Existing entrypoints submit work to one durable Actions owner. Existing workers and provider clients carry out the exact authorized operation and return evidence.

What the overhaul still needs

Permanent work, immutable approved content, durable command receipts, persistent batch membership, crash-safe attempts and honest readback remain necessary. Existing in-process write grants and best-effort post-call logs do not retain an unknown provider result after a crash.

The correction is to attach those guarantees to working provider and worker infrastructure. It does not require rebuilding login, review management, ASO generation or the queue system.

Proof before activation

  1. Consolidate authentication and endpoint ownership; test the real session-manager contract.
  2. Enforce a single guarded write boundary, including permissions, attribution and billing.
  3. Run a complete review journey and the existing approve/wait/resume ASO journey through real entrypoints.
  4. Prove migration conservation, old-sender exclusion, crash recovery, stale approvals and pagination.

Validation is incomplete. Latest remote feature CI is not green: API integration and Actions reliability failed. Both identified CI failures have focused local fixes: scoped page context and the history-query fixture. A complete green replacement run remains required. Isolated passing tests do not prove the composed architecture.
