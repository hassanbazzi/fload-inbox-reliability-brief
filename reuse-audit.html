The branch expanded into capabilities Fload already has. We found duplicated provider paths, an unnecessary authentication detour, and an unresolved split in write ownership. These need consolidation before activation.

Correction in progress. Consolidation and current-policy composition are published on the feature branch. Local validation passes; replacement remote CI and production cutover remain incomplete. The overhaul is not deployed or ready to merge.

What has actually changed

Feature head 6b523d74a is published in the same draft PR. The duplicate listing source and forced Chromium setup are removed. Durable review writes use the existing execution kernel, individual-key client and SRP transport. The speculative account-wide locking and extra browser-execution drafts are withdrawn.

Current access uses current facts. Actions now constructs permissions inside its transaction. The existing auth owner checks retained users, API keys and impersonation. The existing billing and feature owners supply uncached facts without a second policy engine. Review delivery keeps its existing zero-credit cost.

Proved review journey: exact approval → current access → existing write kernel → one native request → durable acknowledgment. Replaying does not send again. Revoking membership after inspection retains the evidence and prevents the POST. Tests use real PostgreSQL and synthetic provider transport, not live customer writes.

Validation: 10,463 API unit tests passed (four existing skips), plus the combined API typecheck and targeted SQL tests for current access, policy, transactions and review delivery. Every SQL checkpoint applies all 175 main and 13 metrics migrations fresh and repeats them unchanged. The earlier complete Actions suite passed 1,087 tests at 9f411aa3f. The new remote CI run is pending; no all-green claim.

Not finished: request, OAuth and automatic-agent integration; exclusive old-sender handoff; real UI/entrypoint journeys; conservation migration and retirement of the old lifecycle. The new runtime is still inactive. No production deployment or main merge.

The intended ownership

Existing entrypoints submit work to one durable Actions owner. Existing workers and provider clients carry out the exact authorized operation and return evidence.

What the overhaul still needs

Permanent work, immutable approved content, durable command receipts, persistent batch membership, crash-safe attempts and honest readback remain necessary. Existing in-process write grants and best-effort post-call logs do not retain an unknown provider result after a crash.

The correction is to attach those guarantees to working provider and worker infrastructure. It does not require rebuilding login, review management, ASO generation or the queue system.

Proof before activation

  1. Consolidate authentication and endpoint ownership; test the real session-manager contract.
  2. Enforce a single guarded write boundary, including permissions, attribution and billing.
  3. Run a complete review journey and the existing approve/wait/resume ASO journey through real entrypoints.
  4. Prove migration conservation, old-sender exclusion, crash recovery, stale approvals and pagination.

Validation is incomplete. The previous cleanup CI passed Actions reliability, types, lint, package tests and web E2E, but failed API unit and integration fixtures. Those fixtures are repaired and locally verified, including safe waiting for a test database to close. Replacement CI at 6b523d74a is pending. Isolated passing tests do not prove the composed architecture.
