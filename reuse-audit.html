What has actually changed

Feature head 641b73b86 is published in the same draft PR. Duplicate description-only listing code, forced Chromium setup, the private review cookie cache and extra account lease are removed. Review capture uses the existing encrypted session cache and login lock.

One review request owner. Old and durable writes now share the Apple client’s request encoder. Editing uses the existing create/update POST; delete/recreate and its repair retry are removed. A failed edit leaves the prior reply intact. Legacy fallback still awaits exclusive sender retirement.

Receipts keep their original authority. All materializers authorize the original ticket and every approved child before replay or conflict details. Recovery reuses canonical request permissions. Changed input cannot authorize an old receipt.

Existing owners, connected. Canonical auth and existing billing/feature policies supply current authority. Shared review policy lives outside the Apple adapter. The selected-row client loader reuses existing credential selection and fixes the mixed-key signer bug. ASO’s approve/wait/resume behavior retains its existing owner.

Reads are wired. The branch registers Actions inbox, detail, history, membership and personal reads. Pagination/count and tenant checks pass. Marking read leaves the shared ticket, approval and attention capacity unchanged.

Approval is durable. The server samples acceptance after validation and planning. Expired positive Undo windows roll back before commit; retries use the same key. Commit/network latency can still consume the remaining visible window.

Proved composed journey: SDK → session/API-key authorization → command transaction → SQL worker → existing credential loader and write kernel → one POST → captured acknowledgment/readback. Lost HTTP responses and duplicate deliveries do not resend. Membership revocation after inspection prevents sending. Only provider HTTP and external session transport are simulated; producer setup is a fixture.

Identity is explicit. Official Apple API IDs, original WebObjects IDs and Play IDs now occupy distinct namespaces in the existing registry. The tested migration preserves tickets, content and receipts, adds no table, and removes the old fallback scan. It never guesses that two IDs represent the same physical review.

Current validation: 10,514 API unit tests, 532 Apple package tests, 23 session tests and 77 focused SQL cases pass, alongside typechecks and scoped lint. The full reliability suite passed 1,247 SQL cases and eleven worker cases. The subsequent provider cleanup passes 531 remaining Apple tests, typechecks, lint and eighteen source-capture SQL cases. All required test blocks passed at cleanup commit f76b2262c, including integration, Actions migrations and web checks. The new intake/read integration has separate local validation; CI for head641b73b86 is pending.

Further overlap removed: ASO localization PATCH calls now share the existing Apple package’s request encoder. The unused browser-write prototype and browser-only binding adapter are deleted. Authenticated original-review capture exposes reads only.

Not finished: complete producer/recovery permissions; OAuth/channel/automatic producer integration; exclusive old-sender handoff; conservation and old-lifecycle retirement; full UI/MCP/load journeys. Commands and provider workers remain unregistered. No production deployment or main merge.

What the overhaul still needs

Permanent work, immutable approved content, durable command receipts, persistent batch membership, crash-safe attempts and honest readback remain necessary. Existing in-process write grants and best-effort post-call logs do not retain an unknown provider result after a crash.

The correction is to attach those guarantees to working provider and worker infrastructure. It does not require rebuilding login, review management, ASO generation or the queue system.

Integration now added

Reliable intake retry: the existing review source capture and insertion owner now replay the authored request before another provider read. Migration0176 extends the command digest guard only: no table or column. Populated upgrades preserve old receipts. Validation: 154 SQL cases, API types and lint.

Existing API-key access preserved: the four Actions GET routes reuse the existing read:agents authorization policy. Inbox, history and pinned members paginate under current access; saved cursors stop working after revocation. Personal-read POSTs remain session-only. Validation: fifteen SQL cases, 52 route/authorization cases, types and lint. Both SQL checkpoints apply 177 main and thirteen metrics migrations fresh and repeat unchanged.

Still incomplete: historical review conservation, listing command/delivery integration, producer handoff and retirement of the old lifecycle. These changes do not activate a second sender.

Proof before activation

  1. Consolidate authentication and endpoint ownership; test the real session-manager contract.
  2. Enforce a single guarded write boundary, including permissions, attribution and billing.
  3. Run a complete review journey and the existing approve/wait/resume ASO journey through real entrypoints.
  4. Prove migration conservation, old-sender exclusion, crash recovery, stale approvals and pagination.

Activation remains gated. Earlier green CI does not certify the current cleanup. Cleanup CI passed at f76b2262c and the newer integration passes its local checks; new-head CI is still required. The composed tests establish this approval/delivery path, not complete producer conservation, exclusive ownership or production readiness.
