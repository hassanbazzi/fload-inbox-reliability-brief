# FLO-1355 listing / ASO / ad-provider reuse audit

Read-only audit, 2026-09-21. Compared committed HEAD `d0945bb3ca61370e3d783d4fcec9573f58d66e01` with local `origin/main` `b5253b2d799cf35863a9d0c31e3481762e44afde`. Also inspected the unimplemented binding176 proposal and explicitly identified uncommitted ad-provider drafts. Paths below are relative to `the implementation worktree`. No code/DDL changes, test bootstrap, provider call or production read.

## Main finding

**Apple API support, individual keys, listing creation/update, guarded writes and approve-now/wait-for-release already exist on main.** The new Actions code must reuse that implementation, not claim these are missing capabilities. The actual additional need is exact immutable approval/source/target association and crash-safe per-request outcome ownership. Native6 supplies useful stricter capture behavior but currently sits beside the existing endpoint implementation; consolidate it. Do not add the proposed binding-page/catalog tables before proving that existing observations/receipts cannot hold the needed final facts.

The existing `aso-write-transport.ts`, `guarded-asc-listing.ts`, `asc-release-collections.ts`, `release-state.service.ts` and `editable-release-preflight.ts` are byte-unchanged in the committed main→HEAD diff. The new listing source factories and full-field native port have no active producer/dispatcher caller found; the description reader's only non-test consumer is the new inactive listing source factory. No committed Apple Ads transport/gateway/credential change exists in this diff.

## Ad providers

**REUSE** the existing Apple Ads package, token-provider adapter, `apple-api-gateway.ts:98,244`, and `guarded-asa-gateway.ts:19`: seven registered mutation families and a narrowed readback client are already installed. Main→HEAD has **no committed changes** in `services/apple-search-ads`, `routes/apple-search-ads` or `packages/apple/src/apple-ads-api`. There is no evidence supporting another Ads auth/transport/policy stack.

**REMOVE from this listing slice** the uncommitted generic provider dispatch and ASA resource-identity placeholder (`actions/resource-identity.ts:17`, `actions/providers/apple-search-ads/resource-identity.ts:23`) until an actual Actions Ads owner consumes them: search found only each other and tests. This is not a recommendation to remove the existing working Ads gateway. The exact native campaign-account key will matter when that concrete owner is integrated; existing gateway/credential/account resolution is the reuse point. No syntax validator proves account authority.

## Smallest consolidation order / proof

1. Delete the unshipped description-specific path by moving its source/tests onto one full-field capture projection. No schema needed.
2. Consolidate native request construction + single-request transport and typed collection decoding inside the existing Apple package. Preserve old callers' behavior intentionally; add explicit retry policy rather than silently changing all sync reads. Port existing `asc-api-client`, `asc-aso-write-transport`, `asc-listing-fetch-api`, native235 and source115 cases.
3. Make the existing release/snapshot reader traverse real continuations and reuse its output for generation and materialization. Test >page, half-locale, empty intermediate, missing requested locale, live/staged separation and stale source. Do not claim an atomic native snapshot.
4. Use one existing approve/wait/resume journey to prove the smallest Actions adapter + durable selected facts. Carry `stage-editable-release-as-ticket`, `editable-release-preflight`, `aso/release-state` and `work-execution/guarded-asc-listing-execution` coverage. Add crash-after-PATCH/late-receipt/source-retirement cases because those are the actual new guarantees. Only then review a minimal migration if existing attempt/observation links are insufficient.

This audit does not recommend reverting correct strictness, weakening source/tenant proof, removing accepted immutable history or silently bypassing current guards. It recommends consolidating the implementation and stopping speculative storage expansion. No tests were rerun during this read-only audit; earlier checkpoint counts are not new evidence.
